## Changes

Single commit (`04235ca`):

1. **Lint — 14 errors, 13 files.** Replaced `new Date()` /
   `Date.now()` with `nowUtc()` from `lib/time/`. All call sites are
   server-side (admin actions, auth actions, member dashboard, privacy
   API routes). Each file picked up an `import { nowUtc } from
   '@/lib/time';`.
2. **Format — 98 files.** `pnpm format` (prettier --write). Pure
   whitespace; no semantic changes outside the targeted fixes.
3. **Test — `member-detail-page.test.tsx:336`.** Seven admin pages
   carry near-identical inline `formatUtcAndCentral` helpers; each
   built the UTC string via `Intl.DateTimeFormat('en-CA', { hour12:
   false })`. On Linux Node ICU that emits `hour='24'` for midnight
   (rotated the displayed date back to the prior day); on Windows
   local it emits `'00'`. Switched all 7 UTC branches to
   `date.toISOString()` slicing — ECMAScript-defined, locale-stable,
   ICU-invariant. The Central branch already normalised
   `'24' → '00'`; left as-is.
4. **Test — `no-naked-date.test.ts` sub-cases 2 & 3.**
   typescript-eslint v8 caches the TypeScript Program after the first
   `lintFiles()` call. Sub-case 1 (7s cold-start) built the Program;
   sub-cases 2 + 3 then materialised new fixture files *post-build*,
   which the Program flagged as "not in tsconfig project" and skipped
   rule evaluation entirely — making the `hasNoRestrictedSyntaxFinding`
   assertion silently return `false`. Fix: materialize all fixtures
   upfront in `beforeAll()`. The per-sub-case `materializeFixture`
   calls are now idempotent overwrites; left in place so each sub-case
   reads as a self-contained unit.
5. **Vercel deploy.** Cascaded from #1; once lint passes, `next build`
   succeeds.

## Decisions

- **`toISOString()` slicing over `if (h === '24') h = '00'` patching.**
  The narrow fix would have mirrored the existing Central-branch
  normalisation. The wider fix removes the entire class of ICU-variance
  bugs by going through ECMAScript-defined output that doesn't touch
  CLDR. Cost: 7 nearly-identical edits + comment. Benefit: no future
  Node-version-dependent failure mode in any of those 7 surfaces.
- **Materialise all fixtures in `beforeAll()` over disabling typed
  parsing per test instance.** Both fix the symptom. Disabling the
  typed parser was a one-line change but would have meant the test
  exercised the rule against a non-typed AST — which is
  *technically* sufficient for a syntactic rule like
  `no-restricted-syntax` but drifts the test from the production
  parser path. Upfront materialisation keeps the test exercising the
  real parser configuration; the cost is one `FIXTURE_TARGETS` array
  at the top of the test file.
- **Direct push to main, no PR.** Consistent with how prior CI-fix
  shifts have been handled on this branch (e.g.
  `2026-05-09-02-lighthouse-perf-fix`). Single-commit, fully
  verified locally, no behaviour change beyond the documented
  fixes.

## Notes for future me

- **typescript-eslint v8 with `parserOptions.project` caches Programs
  by tsconfig path.** Files created at runtime by a test that calls
  `eslint.lintFiles()` will be missed if the Program was built before
  the file was written. The "fast" lint result (20ms vs 7s for the
  cold start) was the clue — the parser was emitting a "not in
  project" error and skipping all rules, so the assertion that "no
  findings" silently succeeded for tests that *expected* no findings.
  Watch for: when a Program-cached test infrastructure produces
  surprisingly fast results, suspect parser short-circuit before rule
  evaluation.
- **Intl `'en-CA'` `hour12: false` is not locale-stable.** Some ICU
  builds emit `'24'` for midnight and roll the date back; others emit
  `'00'`. Prefer `Date.prototype.toISOString()` for UTC display
  strings — it's ECMAScript-defined and runtime-invariant. Reserve
  `Intl.DateTimeFormat` for **non-UTC** zones where you actually need
  the zone projection.
- The lint-test failure (`tests/lint/no-naked-date.test.ts`) was
  invisible locally because Windows + the Node version on this
  machine happened to take a code path that did include the
  late-materialised files. Adding a "linux-shaped" CI smoke locally
  (e.g., via WSL or a quick devcontainer) before merging
  cross-platform-sensitive code would have caught both this and the
  `'24'`-hour bug on the local pass.

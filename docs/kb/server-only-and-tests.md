# `server-only` import + vitest module-load

Linked ADR(s): 0007 (server-only secret discipline), 0006 (first cycle to need the test mock for a server-only library).

The `server-only` package's `index.js` intentionally throws when imported in a non-server context — it is the runtime guard that tells you a server-only module accidentally landed in a client bundle. Inside vitest, that throw fires at module-load time and blows up every test in any file that imports the server-only-marked module, before collection.

## Lessons

- **2026-05-10** — Files that `import 'server-only'` cannot be imported by vitest tests without mocking the package. Use `vi.mock('server-only', () => ({}))` at the top of the test file. *Context:* ADR-0006 cycle 2 t6 attempt 1 — `tests/audit/with-audit.test.ts` imports `lib/audit/withAudit.ts`, which has `import 'server-only';` as its first line per ADR-0007. The validator failed at module-load time with the package's intentional non-server-context throw; the entire test file failed before any sub-case ran. *Why it matters:* The repo already had this pattern in `tests/seo/*-jsonld.test.ts` files — the fix is a one-liner at the top of the test file: `vi.mock('server-only', () => ({}))` (vitest globals must be enabled OR import `vi` from `vitest`). The mock returns an empty module object, which is what `import 'server-only'` actually is in the package's runtime — the throw is the side effect, not an export. Future test files that touch `lib/{audit,supabase,stripe,...}/*.ts` should pre-load this pattern; the alternative (refactoring the production code to remove `import 'server-only'`) would weaken the ADR-0007 posture and is the wrong direction.
- **2026-05-10** — The `import 'server-only'` line itself is asserted by AC9.8 via static source-text check, NOT via dynamic import. *Context:* ADR-0006 cycle 2 t6 sub-case 8 — `tests/audit/with-audit.test.ts` reads `lib/audit/withAudit.ts` via Node's `readFileSync` and asserts the first line equals `import 'server-only';`. *Why it matters:* The `vi.mock` shim hides whether the import is actually present at runtime — a worker who deletes the line and adds the mock would still see green tests. The static source-text assertion is the cheap defense-in-depth that catches the regression. Reuse this pattern for any file whose `server-only` import is load-bearing for ADR-0007 compliance.
